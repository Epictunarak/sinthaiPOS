# data/ — ข้อมูลต้นทาง (source of truth)

ไฟล์ในโฟลเดอร์นี้คือข้อมูลที่ **คนดูแลด้วยมือ** และเป็นต้นทางของทุกอย่างที่เหลือในระบบ
ทั้งฐานข้อมูล PostgreSQL และแผ่น Products ใน Google Sheet ล้วนถูก *สร้างจาก* ไฟล์เหล่านี้

## ที่มาของข้อมูล

แปลงมาจาก `สินไทยพาณิชย์ Brand Search Template completed.xlsx`
(ชีต `SKU Price Comparison` และ `Brand_Sorted_Search`, ข้อมูลสำรวจราคาวันที่ 2026-05-16)

## ไฟล์

| ไฟล์ | เนื้อหา | แก้ไขอย่างไร |
|---|---|---|
| `products_master.csv` | ตัวตนสินค้า: SKU, บาร์โค้ด, แบรนด์, ชื่อ, หมวด, ขนาดบรรจุ, ราคาขาย | แก้ด้วยมือ |
| `vendor_prices.csv` | ราคาที่สำรวจได้จาก Makro / Lotus / BigC พร้อมแหล่งอ้างอิง | แก้ด้วยมือ |

## สิ่งที่ **ไม่** อยู่ในไฟล์เหล่านี้ โดยตั้งใจ

**ต้นทุน กำไร และราคาขายส่ง ไม่ถูกพิมพ์เก็บไว้** เพราะเป็นค่าที่ *คำนวณได้*
จาก `vendor_prices.csv` ถ้าพิมพ์มือเก็บไว้ พอราคา Makro เปลี่ยน ตัวเลขจะค้างอยู่กับอดีต
โดยไม่มีใครรู้ตัว

ค่าเหล่านี้ถูกคำนวณสองที่ และทั้งสองที่ต้องให้คำตอบตรงกันเสมอ (มีเทสต์คุมอยู่):
- `scripts/build_catalog.py` — ใช้ตอนยังไม่มีฐานข้อมูล
- `sinthai.product_margin_view` — ใช้ตอนระบบรันจริง

## ทำไมต้องมีคอลัมน์ `vendor_role`

`Makro` = **supplier** (ราคาที่เราซื้อเข้า = ต้นทุน)
`Lotus` / `BigC` = **competitor** (ราคาที่ลูกค้าเทียบได้ = เพดานราคาขาย)

workbook เดิมไม่แยกสองอย่างนี้ ทำให้คำนวณกำไรไม่ได้
รายละเอียดเต็มอยู่ใน [`../docs/DATA_FINDINGS.md`](../docs/DATA_FINDINGS.md)

## ทำไมต้องมีคอลัมน์ `price_basis`

ราคาบางแถวเป็นราคา *ต่อชิ้น* บางแถวเป็นราคา *ต่อลัง* ถ้าเทียบกันตรงๆ ตัวเลขกำไรจะเพี้ยน
หลายเท่า (เคสจริง: Coke ลัง 24 ดูเหมือนกำไร 2,144% ทั้งที่ขาดทุน 6.6%)
ทุกราคาจะถูกแปลงเป็น "ต่อแพ็ค" ก่อนนำไปเทียบเสมอ

## เมื่อแก้ไขไฟล์เหล่านี้แล้ว

```bash
# 1. ดูผลกระทบต่อกำไรก่อน
python3 scripts/build_catalog.py

# 2. สร้างไฟล์ผลลัพธ์ลง build/
python3 scripts/build_catalog.py --write

# 3. นำเข้าฐานข้อมูล (ดู ../README.md)
```

`build/` เป็นผลลัพธ์ที่สร้างใหม่ได้เสมอ จึงไม่ถูก commit เข้า git
