# tests/e2e — ทดสอบโดยขับแอปจริงในเบราว์เซอร์

## ทำไมต้องมี

Unit test ตรวจได้แค่ว่าฟังก์ชันคำนวณถูก แต่บั๊กที่เจอจริงตอนพัฒนาคือ:

- **ปุ่ม "บันทึก" ในหน้าตรวจนับหลุดออกนอกจอมือถือ** — โค้ดทำงานถูกทุกบรรทัด แต่คนที่ยืนนับของ
  อยู่หน้าชั้นกดไม่ถึง ซึ่งเป็นปุ่มหลักของหน้านั้นทั้งหน้า
- **ป้ายสถานะตัดบรรทัดจนกลายเป็นวงกลมบิดๆ** เพราะ `border-radius: 999px` เจอข้อความสองบรรทัด
- **หน้าจอขึ้นคำว่า `#undefined`** ให้พนักงานเห็นเมื่อ server ไม่ส่งเลขที่บิลกลับมา

ทั้งสามอย่าง unit test จับไม่ได้เลย ต้องเปิดแอปจริงบนขนาดจอจริงเท่านั้น

เทสต์ชุดนี้จึงเน้น flow ที่ **เกี่ยวกับเงินและสต็อก** เป็นหลัก

## วิธีรัน

ต้องเปิด 3 อย่างตามลำดับ (คนละ terminal หรือรันเป็น background)

```bash
# 1. เปิด mock backend (ใช้ข้อมูลสินค้าจริง 141 รายการจาก data/products_master.csv)
node tests/e2e/mock-api.mjs

# 2. build แอปให้ชี้มาที่ mock แล้วเปิด preview
cd web
VITE_API_BASE_URL=http://localhost:5599/ VITE_API_TOKEN=test npm run build
npx vite preview --port 4173

# 3. รันเทสต์
npm install --no-save playwright-core      # ครั้งแรกครั้งเดียว
node tests/e2e/smoke.mjs
```

ถ้า Chrome ไม่ได้อยู่ตำแหน่งมาตรฐาน ให้ระบุเอง:

```bash
CHROME_PATH="C:/Program Files/Google/Chrome/Application/chrome.exe" node tests/e2e/smoke.mjs
```

## ครอบคลุมอะไรบ้าง

| กลุ่ม | ตรวจอะไร |
|---|---|
| ทุกหน้า | ไม่ล้นขอบจอที่ความกว้าง 390px (ขนาด iPhone 14) |
| เก็บบาร์โค้ด | ปฏิเสธหลักตรวจสอบผิด, ปฏิเสธบาร์โค้ดซ้ำ, ออกรหัสภายใน, บันทึก, แถบความคืบหน้า |
| ตรวจนับ | ปุ่มบันทึกกดถึงจริง, คำนวณส่วนต่างถูก, ปฏิเสธจำนวนติดลบ |
| ขายของ | เพิ่มตะกร้า, ส่วนลด, บันทึกการขาย, ไม่โชว์คำว่า undefined, ล้างตะกร้า |
| ทั้งหมด | ไม่มี JavaScript error ระหว่างใช้งาน |

## หมายเหตุ

`playwright-core` ไม่ได้อยู่ใน `package.json` โดยตั้งใจ เพราะเป็นเครื่องมือทดสอบที่ต้องมี
เบราว์เซอร์ในเครื่องอยู่แล้ว ไม่ควรบังคับให้ทุกคนที่ `npm install` ต้องโหลดตาม
